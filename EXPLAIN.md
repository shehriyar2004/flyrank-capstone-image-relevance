# Explaining this capstone

This project was built with AI assistance, documented in `BUILDLOG.md`. Before a review, read the small modules below and explain their behavior in your own words.

## The pipeline

When a caller submits an image batch or article, the HTTP handler validates the request, authenticates a tenant, and saves a job. It returns `202` promptly. A separate worker makes the slow AI calls, validates their outputs, stores captions/subject intent and embeddings, and records progress and cost. Requests can inspect the job while it runs.

## What an embedding means

An embedding is a list of numbers generated by a real model from the text. Similar meanings tend to point in similar directions. `cosine()` in `src/matching/rank.mjs` divides the dot product by the vectors' lengths, so it compares direction rather than vector magnitude. It rejects empty, zero, nonfinite or incompatible vectors. Filenames and expected evaluation image IDs do not contribute to similarity.

## Why the wolf is refused

`src/matching/guard.mjs` checks several independent conditions. The post must be ready and its subject clear. The image must have validated, confident metadata. Its normalized subject must agree with the post, and the embedding similarity must pass the calibrated cutoff. A high similarity cannot overrule a fox/wolf subject mismatch. Ambiguous expressions such as `fox or wolf` are refused rather than resolved to the first word.

The model can still misidentify a picture with high self-reported confidence. The guard reduces known mistakes; it does not make vision AI infallible. That is why the project records explanations, measures results and supports human review.

## Why retries do not duplicate results

`src/data/repository.mjs` stores an idempotency key together with a hash of the request. The same key and request return the saved response. The same key with changed data returns `409`. The action and response are committed in one database transaction, preventing two simultaneous retries from creating two posts.

The worker separately uses durable stage results and unique owner/version constraints. A retry can reuse validated tags or an embedding that was already stored. An actual repeated model call is still counted as a separate attempt; the project does not falsely promise exactly-once external inference.

## Why a crashed worker cannot overwrite a new worker

`src/jobs/queue.mjs` claims one job under a database lock and gives it a lease token. Heartbeats renew that lease. If the worker disappears, another worker can reclaim the expired job. Every result write checks the current token and lease, so an older worker cannot publish after losing ownership. Three failures create a persistent alert instead of retrying forever.

## Why approval checks the current evidence

`src/services/reviews.mjs` locks the suggestion, post and image in its transaction and calls the guard using that same database connection. This avoids exhausting the pool during concurrent requests. Approval checks metadata, threshold and embedding revisions; a stale suggestion cannot be approved after its evidence changes. The stored explanation remains an immutable record of the original selection.

## What the precision number means

Calibration and evaluation use different labeled posts. Calibration selects the similarity cutoff; it is frozen before held-out evaluation. Top-1 precision here means the number of positive evaluation posts whose first accepted image equals the visually justified label, divided by all positive evaluation posts. A refusal counts as a miss. Coverage tells you how often the system suggested anything. An absent-subject refusal is reported separately and does not inflate the precision denominator.

## Why free calls still have a budget

Every actual local inference attempt records its tenant, job/entity, immutable model identity, status, duration, usage when known, and `$0` API cost. A transaction reserves a call-budget slot before inference. Concurrent requests cannot exceed that budget, which prevents uncontrolled CPU work even when no provider charges money.

## Demonstration

Follow the README run/seed steps, wait for the job IDs to finish, and run `npm run probe`. Inspect the common-name and scientific-name fox suggestions, forced-wolf rejection, absent-octopus refusal and cost log. Use `GET /suggestions/:id` to read an explanation, then the review endpoint to approve or reject it. Never paste `.env` values into a public issue or commit.
